# Проверка реализации

Проверено 6 ноября 2026 года на Windows x64, RTX 3070 Laptop 8 ГБ.

- Release-сборка C# завершилась успешно; опубликован self-contained EXE с .NET runtime. При последней публикации онлайн-аудит NuGet был недоступен из изолированной сети (NU1900); это не помешало восстановлению и сборке.
- Регрессионные сценарии покрывают атомарную память, загрузку/восстановление, конкурентное сжатие, забывание, разрешения, файловые изменения, подтверждения, backup, полный доступ, браузер и профиль пользователя. Дополнительно проверяются чистота ролей диалога, отсутствие двойной отправки вопроса, изоляция служебных данных от речи/действий, повторная генерация дублей, сохранение имени и темпа инициативы при перезапуске.
- Финальный обычный набор: **88 passed, 0 failed**.
- Отдельное отношение: JSON и Markdown-проекция, восстановление из backup, сохранение при забывании диалога; неизвестный и другой собеседник не переписывают отношение к основному пользователю.
- Браузер: шесть сценариев с подставным источником документа проверяют передачу настоящего текста/URL в пересказ, разрешения, ошибки, обрезку, отмену и маршрутизацию. Нативный UI Automation ABI проверен на собственном скрытом тестовом контроле (TextPattern/GetText, свойства и поиск); содержимое пользовательских вкладок не читалось.
- Реальные локальные модели: русский запрос → английский ответ; чтение воспоминания после перезапуска; сжатие памяти моделью; пересказ фактов из настоящего `documents/example.md`; создание и отклонение запроса запуска калькулятора без ложного сообщения о выполнении.
- Vision: модель правильно прочитала слово TEST на искусственном красном изображении.
- Piper → WAV → Whisper: женская английская речь синтезирована и распознана локально.
- Устройства звука и native-системный контекст перечисляются; захват клавиши/запись реализованы, но реальная речь пользователя при разработке не записывалась.
- Windows Job: принудительное завершение тестового родительского процесса немедленно завершило его дочерний процесс.
- `Start.cmd --diagnose`: все пути моделей/движков существуют; запуск через Windows PowerShell 5 проверен.
- Дополнительный `--feature-smoke` прошёл с настоящей моделью: структурированный ответ обновил отдельное отношение, просмотренные создание/редактирование применились только после одобрения с backup, модель пересказала конкретные факты из искусственного текста браузера. Все данные этого сценария находятся в отдельном `data/development-checks/feature-smoke-*`.
- Расследование качества диалога воспроизвело исходный ответ «Hello, User. What is your name?» на Qwen2.5-VL-3B с настоящей сохранённой историей. Переполнение контекста не подтвердилось. Найдены конфликт имени `User`, заметки модели под ролью пользователя, двойной текущий вопрос и перегруженная генерация речи вместе с JSON.
- После исправлений стандартная модель — Qwen3.5-4B Q4_K_M. Финальный `--dialogue-smoke` прогнал восемь предоставленных Владом сообщений, продолжение темы, имя после перезапуска и старую загрязнённую историю: ответы остались английскими, без соседних повторов, имя Влад воспроизведено во всех трёх проверках, роли не перепутались. Отчёт: `data/development-checks/dialogue-smoke-20261107-010024-63c199/report.json`. Два предварительных прогона помечены неуспешными после проверки смысла, а не скрыты формальными проверками.
- Остались качественные ограничения: иногда появляются лишние вопросы, абстрактные фразы и уклончивость. Этот прогон подтверждает исправление конкретных ошибок, а не гарантирует качество большой облачной модели или человеческой беседы.

Реальный GDI-захват экрана из изолированной сессии разработки вернул Win32 error 5 (Access Denied). Это обработано без остановки диалога. Требуется проверить `/look` при обычном интерактивном запуске; доступ к реальному рабочему столу не был подтверждён этой проверкой.

