# ComputerNeighbour

Переносимый консольный компаньон для Windows 10/11 x64 на C# / .NET 10. Локальные Qwen3.5-4B, Whisper и Qwen3-TTS работают без облачного аккаунта и API-ключа. Модели и движки загружаются в эту папку. Опубликованное приложение содержит .NET runtime.

## Запуск

Дважды щёлкните **Start.cmd**. Дождитесь `Ready`, затем пишите по-русски или по-английски. Персонаж отвечает по-английски текстом и женским голосом. Начальный персонаж — Evelyn; его описание можно полностью заменить.

**Удерживайте F10**, говорите, затем отпустите. Микрофон открывается только на время удержания, с пределом 30 секунд; затем выполняется распознавание. F10 работает и вне окна консоли, но сама клавиша не блокируется для других приложений. В конфиге можно назначить другую клавишу. Во время прослушивания озвучивание прерывается.

Примеры запросов:

```text
Привет! Запомни, что я люблю научную фантастику.
Read this article and tell me its main point: https://example.org/article
Read documents/notes.md and remember the main points.
Open calculator.
```

Evelyn может посмотреть на основной монитор, когда вопрос требует текущего изображения, например «Чем я сейчас занят?». Команда `/look` вызывает снимок напрямую. Программа сообщает о действии заранее и отличает успешное наблюдение в этой сессии от текущего доступа. Для чтения текущей страницы браузера используйте `/browser` или «Прочитай текущую вкладку браузера». Публичную ссылку можно передать отдельно.

Для визуального поиска через браузер включите `/desktop on` и введите `/google` с вопросом, например `/google Какой картиной вдохновлена эта иллюстрация?`. Перейдите к изображению на основном мониторе, наведите указатель на один угол и нажмите **F8**. Повторите на противоположном углу того же окна. Второе нажатие подтверждает отправку выделенной области в Google. До захвата можно отменить выбор клавишей **Esc**. Evelyn открывает Google AI Mode в новом окне Chrome, прикрепляет фрагмент, задаёт вопрос и пересказывает прочитанный ответ. Для этого нужны доступный Google AI Mode и разрешения на снимок, поиск, чтение браузера, запуск приложений и управление рабочим столом.

Если на мониторе открыта фотография, «Как тебе это фото?» просит личное впечатление Evelyn. При самостоятельном взгляде на общий экран она может поделиться коротким наблюдением, шуткой или связью с вашим разговором. Если у неё есть только описание того, что уже видно, она оставляет момент без комментария.

Для основного пользователя зарегистрируйте голос командой `/enroll user`, затем удерживайте F10 и произнесите несколько предложений. Других людей регистрируйте отдельно, например `/enroll alice`. Метка `user` связывает ваш голос с сообщениями, набранными в консоли.

Все настройки находятся в **config/appsettings.json**. После изменения настроек перезапустите программу. Файл персонажа **characters/neighbour.md** перечитывается перед ответами.

| `audio.inputDeviceId`, `audio.outputDeviceId` | `-1` — системное устройство; остальные номера показывает `/devices` |
| `audio.pushToTalkVirtualKey` | Windows VK-код: F9=120, F10=121, F11=122 |

| `permissions.allowedApplications` | Словарь разрешённых имён и exe; аргументы и shell-команды модель выполнять не может |

| `permissions.confirmFileChanges` | Подтверждать файловые изменения по запросу пользователя; общий `confirmActions` тоже действует, если не включён `fullFileAccess` |

| `permissions.searchWeb`, `internet` | Поиск в интернете, провайдеры, лимиты результатов и RSS-источники техноновостей |

| `permissions.desktopInput` | По умолчанию `false`; для кликов и ввода установите `true` |
| `permissions.screenCapture` | Общий переключатель скриншотов. По умолчанию включён. Заголовок активного окна на захват не влияет |
| `desktop.excludedWindowTitles` | Не наблюдать экран при активном окне с указанным фрагментом заголовка |

| `observation.keepScreenshots` | `false`: изображения живут в памяти процесса; `true`: хранить последний снимок внутри `data/tmp` |

| `model` | Контекст, температура, потоки CPU, GPU-слои, таймауты и локальные файлы модели |

## Выполнение задач на компьютере

Первый проход выбирает быстрый, обычный или глубокий режим. Глубокий режим выделяет локальной модели больше времени на анализ. Для задач с действиями Evelyn показывает краткий план и журнал фактических результатов. Следующий шаг выбирается после получения результата предыдущего. `/thoughts` показывает выбранный режим и проверки.

В естественной просьбе модель определяет, какие возможности нужны, например поиск, чтение источника и ввод в окно. Исполнитель сверяет шаги с исходной просьбой, разрешениями и доступными инструментами. Если найден каталог, Evelyn может перейти по ссылке из него к самому тексту и перенести точный отрывок в редактор. Подтверждение вроде «Давай» относится к предыдущей просьбе того же пользователя.

Уточняющая просьба может продолжить работу с последним сохранённым результатом после перезапуска. Evelyn читает фактический файл перед правкой. Для рисунка она использует исходный PNG как основу и сохраняет новую версию отдельно. Отзыв без просьбы внести изменение остаётся обычной репликой.

Попробуйте `/work Прочитай documents/input.md, затем сохрани краткую сводку в documents/summary.md и проверь файл`. При включённых подтверждениях Evelyn покажет подготовленное изменение. `/approve N` применит его и продолжит текущий план, а `/reject N` остановит задачу на этом шаге. `/cancel` останавливает план и снимает его ожидающее подтверждение.

`/full access` действует до выхода из приложения или смены режима. Он включает ввод в окна и автоматически подтверждает действия по явным задачам в разрешённых папках и приложениях. `/ask before edit` возвращает подтверждения для изменений, запуска приложений и ввода. `/approve for me` делегирует их на одну задачу. Для ввода в окне вне списка настроенных приложений требуется отдельное подтверждение. `/access default` возвращает значения из конфигурации.

В задаче на сохранение указание «в папку `Documents/Evenlin/`» означает подпапку `Evenlin` в личной папке «Документы» Windows. Evelyn использует указанный каталог и показывает абсолютный путь созданного файла. Для папки внутри ComputerNeighbour используйте `documents/Evenlin/`.

Чтобы управлять открытым приложением, включите `/desktop on`, выведите окно на основной монитор и обратитесь к Evelyn голосом или попросите её открыть настроенное приложение. Она получает изображение активного окна, проверяет окно и фокус перед вводом и повторно осматривает его после действия. Клики рассчитываются по пикселям полученного изображения. Допустимые папки и приложения заданы в `config/appsettings.json`.

На прямую просьбу нарисовать Evelyn создаёт и проверяет новый PNG в `documents/evelyn-sketches`. Если в просьбе указан Paint, она открывает готовый PNG в Paint и ищет окно с именем файла. Этот процесс использует локальный рендерер и разрешения на запись файла и запуск приложения.

Наблюдения и инициативные реплики работают, пока приложение запущено. В тихие часы и при длительной неактивности пользователь не беспокоится; после двух реплик без ответа персонаж ждёт обращения. Модель может выбрать молчание. Инициативные события не выполняют компьютерные действия.

Явные просьбы «называй меня Влад», «будь прямее», «поменьше инициативы», «не говори лишь бы что-то сказать» сохраняются в `data/memory/user-profile.json` из слов основного пользователя. Имя не зависит от сжатия беседы или догадок модели. Просьба снизить инициативу втрое увеличивает интервалы планировщика. «Будь более инициативной» возвращает обычный темп. Более ранняя просьба из сохранённой переписки не отменяет более новую.

После обычного разговора Evelyn может выработать привычку, интерес или собственный вкус. Новый вкус начинается с её конкретной реакции и может закрепиться в другом разговоре или измениться после обратной связи. Эти черты влияют на обычные ответы и выбор темы для самостоятельной реплики. Они хранятся в `data/personality/emotions.json` и доступны через `/character`. При `/forget CONFIRM` характер сохраняется вместе с настроением и отношением.

Эвелин выражает конкретные эмоции в зависимости от ситуации. Доверие влияет на то, насколько откровенно она о них говорит, а выразительная озвучка передаёт смену чувства от предложения к предложению. `/status` показывает до двух чувств, связанных с недавней деталью разговора. Такое послевкусие держится до четырёх следующих обменов или 30 минут в текущем сеансе. Оно сбрасывается при перезапуске и `/forget CONFIRM`. Инкогнито работает с собственной копией.

Настроение — симуляция персонажа: сохраняются доверие, теплота, близость, эмоциональный тон, энергия, стресс, любопытство. На контекст влияют диалог, успех задач, время, день недели, сезон, длительность отсутствия, активное окно, длительность сессии, заряд/питание ноутбука, экономия батареи, свободная RAM и настроенная погода. Системный контекст отключается через `permissions.systemStatus`. Без координат погода не выдумывается.

## Создание и редактирование файлов

Можно обратиться обычным текстом, например `Создай файл documents/note.txt: Remember to take a break.` или `Edit documents/note.txt | take a break | drink water`. Для произвольного задания модель может запросить `create_file` / `edit_file`. Явные команды `/write` и `/edit` работают без необходимости полагаться на выбор инструмента маленькой моделью. Разделители вокруг старого/нового фрагмента в краткой команде не являются частью содержимого; точное содержание со значимыми пробелами можно передать модели как аргументы инструмента.

Изменение сначала готовится без записи целевого файла. Консоль показывает diff, а полное предложение сохраняется в `data/file-proposals/`. По `/approve N` применяется именно просмотренный вариант. Если файл с тех пор изменился, предложение отклоняется. Новые файлы не перезаписывают существующие; при редактировании старая версия сохраняется побайтно в `data/file-backups/` вместе с метаданными восстановления. Сохраняются UTF-8/UTF-16 BOM и стиль перевода строк.

Если хотите выдать полный файловый доступ, измените существующее поле в конфиге на `"fullFileAccess": true` и перезапустите программу. В этом режиме файловые изменения по запросу и по инициативе персонажа выполняются без подтверждения. Резервные копии, проверка размера и границы `writableDirectories` сохраняются. `writeFiles=false` запрещает запись даже при полном доступе; `allowAutonomousFileActions=false` отдельно запрещает инициативные изменения.

Полный файловый доступ относится к выделенной рабочей области внутри ComputerNeighbour. Внутренние настройки, исполняемые файлы, модели, исходники приложения и его память не являются пользовательской файловой областью. Поддерживаются обычные текстовые форматы `.txt`, `.md`, `.json`, `.csv`, `.tsv`, `.html`, `.htm`, `.css`, `.xml`, `.yaml`, `.yml`, `.ini`. Бинарные файлы и исполняемые скрипты этот редактор не меняет.

## Чтение и поиск файлов

«Прочти текст в открытом блокноте PVP1.txt» запрашивает текущий текст соответствующей вкладки Блокнота, включая несохранённые правки. Вкладка должна быть выбрана в своём окне, а окно развёрнуто. Если есть только имя файла, Evelyn сначала проверяет Блокнот, затем ищет точное имя в `permissions.readableDirectories`. Команда «Найди файл PVP1.txt» сообщает, где он находится. При нескольких совпадениях Evelyn попросит точный путь. `Start.cmd --document-diagnose PVP1.txt` проверяет чтение Блокнота без запуска модели и выводит только размер текста.

## Чтение открытого браузера

Откройте нужную страницу в Chrome, Edge, Firefox, Brave, Opera или Vivaldi, ненадолго оставьте окно активным, затем вернитесь в консоль и выполните `/browser`. Приложение запоминает последнее активное окно браузера лёгким опросом. Текст страницы читается только по запросу инструмента, через Windows UI Automation; нажатия клавиш, буфер обмена, отладочный порт и отдельный профиль браузера не используются.

Читается текст документа, предоставленный средствами доступности. Поэтому могут работать уже открытые страницы с JavaScript и авторизацией. Это не гарантирует чтения всей страницы: виртуализованные списки, canvas и ещё не загруженные части могут не предоставлять текст. При нескольких неоднозначных окнах, смене страницы в процессе чтения или недоступном документе приложение сообщает ограничение и не выдаёт заголовок окна за текст статьи. Приватные/исключённые заголовки из `desktop.excludedWindowTitles` блокируются.

Если текст недоступен, но адресная строка читается, `browser.publicUrlFallback=true` разрешает загрузить публичную страницу по этому адресу (только при `permissions.readWeb=true`). В таком случае явно указывается, что cookies браузера не использовались: публичная версия может отличаться от авторизованной. Поддерживаются адресные строки, в которых скрыт префикс `https://`. Команда `Start.cmd --browser-diagnose` проверяет чтение без нейросети и печатает только заголовок, URL, способ чтения и количество символов.

Обращение по имени тоже работает: «Эвелин, можешь прочитать открытую статью в браузере и оценить её». Для гарантированного прямого вызова есть `/browser`.

## Поиск и проверенные источники

Можно прислать голую ссылку либо попросить «Найди последнюю интересную новость из мира техники и дай источник». Для обычного поиска используются публичный HTML-поиск DuckDuckGo и резервный RSS-поиск Bing; API-ключ не нужен. Для свежих общих техноновостей дополнительно используются датированные RSS-ленты издателей из `internet.technologyNewsFeeds`. Адреса, количество результатов, число читаемых статей, лимит текста и окно свежести настраиваются в конфиге. Публичные поисковые страницы иногда ограничивают доступ или показывают captcha; в этом случае приложение сообщает ошибку.

Поиск выполняется по запросу пользователя или когда текущий вопрос требует проверки значения незнакомого термина. Для такого запроса в поисковик уходит только термин с уточнением о значении. Если вы попросите перепроверить определение, Evelyn использует термин из вашего недавнего вопроса. Фоновые события поиск не запускают. После нахождения ссылок приложение загружает статьи и передаёт модели полученный текст. Если доступны только поисковые аннотации, Evelyn сообщает об этом. Старые материалы с известной датой исключаются из свежих новостей.

Ссылки добавляет приложение из результатов настоящих загрузок, а не генератор текста. Выдуманные моделью URL удаляются. Проверенные ссылки, названия и даты сохраняются в `data/memory/web-sources.json`, поэтому `/sources` и «Дай ссылку, пожалуйста» работают после перезапуска. Если для старого ответа нет проверенного источника, приложение прямо это сообщает. `/forget CONFIRM` очищает и эти ссылки. При озвучивании длинные URL не зачитываются — они остаются в консоли.

## Отдельное отношение к пользователю

`data/personality/relationship.json` хранит текущую установку к основному пользователю, последнее впечатление, ценимые качества, опасения, границы, доверие, теплоту и близость. Рядом находится читаемая проекция `relationship.md`; каноническим состоянием служит JSON. Модель получает эту запись перед ответом и обновляет её отдельно от фактической памяти и проходящего настроения. Посмотреть её можно командой `/relationship`.

Запись меняется от взаимодействий с основным пользователем (`user` или зарегистрированное имя из `userName`). Другие и нераспознанные голоса не переписывают его отношение и показатели доверия; они могут влиять на проходящее настроение. `/forget CONFIRM` очищает память диалога и оставляет отношение отдельно.

## Память по задачам

Обсудите, где остановились, и скажите «Запомни, где мы остановились с письмом». Evelyn сохранит цель, прогресс и следующий шаг из разговора. «Продолжим с письмом» или «Что осталось по задаче „Письмо“?» покажет сохранённую запись. Если подходят несколько задач, можно ответить названием или номером. Записи сохраняются при перезапуске и сжатии диалога.

- «Привяжи documents/письмо.md к задаче Письмо» добавит файл. Таким же способом можно привязать URL.
- «Найди время встречи в файлах задачи Письмо» покажет строки из привязанных текстовых файлов. «Сравни версии задачи Письмо» сравнит два последних привязанных текстовых файла. Привязывайте сначала старый, затем новый.
- «Напомни завтра продолжить» установит напоминание для активной задачи на 09:00 по местному времени. Можно указать время или интервал, например «Напомни через полчаса продолжить задачу Письмо». Evelyn напомнит при работающем приложении или после следующего запуска, если срок уже прошёл.

## Qwen3.8 для сложных задач

`Setup.cmd -Only Qwen3.8 -SkipBuild` добавляет переносимую Ollama и проверенную сборку `qwen3.8:27b` Q4_K_M. Веса занимают около 18 ГБ. На RTX 3070 с 8 ГБ видеопамяти Ollama распределяет работу между GPU и CPU. [Карточка модели](https://ollama.com/library/qwen3.8:27b)

Когда первый проход выбирает `deep` для текстового диалога или многошаговой задачи, Эвелин запрашивает у Qwen3.8 разбор или начальный план. В запрос попадают текущая задача и короткий контекст. Эвелин использует выводы при подготовке ответа или выборе следующего разрешённого действия. Для ответа и выполнения шагов она возвращается к Qwen3.5-4B. После паузы на согласование рабочий процесс продолжает использовать уже полученный план.

Во время анализа Эвелин освобождает видеопамять своей модели. Ollama запускается на локальном адресе с отключёнными облачными функциями и выгружается после запроса. `/cancel` прерывает анализ. Если Qwen3.8 недоступна, истёк таймаут или она вернула неполный ответ, запрос продолжает обычный `deep` на 4B.

`/status` показывает доступность Qwen3.8. Для отключения задай `model.deep.enabled` равным `false`. `model.deep.timeoutSeconds` задаёт лимит анализа, по умолчанию 6 минут. В инкогнито, во время обучения LoRA и с внешним сервером `model.autoStart=false` сложные запросы обрабатывает 4B. Служебный ключ Ollama создаётся при первом запуске в каталоге `.ollama` профиля Windows. [Справка Ollama](https://docs.ollama.com/faq#where-can-i-find-my-ollama-public-key)

### Профиль с аблитерацией

`Setup.cmd -Only Abliteration` устанавливает Qwen3.5-4B Amadeus с поддержкой изображений и Huihui Qwen3.8-27B для сложных задач. В обеих моделях авторы изменили веса методом аблитерации, чтобы сократить число отказов. Пара занимает около 21 ГБ. [Карточка Amadeus](https://huggingface.co/Jitheswar/Qwen3.5-4B-Amadeus) · [Карточка Huihui](https://ollama.com/huihui_ai/Qwen3.8-abliterated:27b)

При `model.abliterated=null` приложение выбирает эту пару после успешной установки. Значение `false` возвращает исходные модели при следующем запуске. `true` выбирает профиль с аблитерацией явно. `/status` показывает тег модели для сложных задач, а при запуске выводится имя GGUF для диалога.

## Инкогнито

`/start incognito` открывает эксперимент на копии текущего диалога, памяти, профиля, характера, настроения, отношений и задач. Копия живёт в оперативной памяти. `/status`, `/memory`, `/relationship` и `/thoughts` показывают состояние активного сеанса. Даже `/forget CONFIRM` в инкогнито действует на временную копию.

`/stop incognito` возвращает обычный сеанс. При закрытии приложения временная копия исчезает, а следующий запуск загружает обычное состояние с диска. Фоновые события обычного сеанса ждут возврата. Для экспериментов доступны текстовый ввод, озвучка ответов и локальный просмотр с текущими разрешениями на чтение. Озвучка использует настроенный голос и воспроизводит звук прямо из памяти. Микрофон доступен в обычном сеансе. История прокрутки терминала относится к самому терминалу.

При первом входе в инкогнито запись сырого вывода локальной модели в диагностические файлы приостанавливается до перезапуска. Это защищает от поздней записи строк, оставшихся в буфере процесса после эксперимента.

## Дообучение реплик с LoRA

`Setup.cmd -Only LoRA` устанавливает локальный тренер и веса исходной Qwen3.5-4B. Для профиля с аблитерацией используйте `Setup.cmd -Only LoRA -Abliterated`. Для установки нужен Windows x64 Python 3.12–3.14. Для обучения нужна CUDA на NVIDIA с поддержкой BF16 и от 5 ГиБ свободной видеопамяти перед загрузкой. Установите `model.autoStart=true`. Веса для обучения занимают около 9,3 ГБ на профиль, окружение Python с CUDA требует дополнительное место. Профили используют общие одобренные примеры и хранят адаптеры отдельно.

1. После подходящей реплики в обычном чате введи `/lora good`, чтобы сохранить пару «вопрос и ответ». `/lora teach ПРЕДПОЧТИТЕЛЬНЫЙ ОТВЕТ` сохраняет твой вариант ответа на ту же реплику. Для ответов используй английский. `/lora examples` показывает примеры, `/lora remove НОМЕР` убирает пример из следующего запуска.
2. Собери от 4 до 32 коротких самостоятельных пар и запусти `/lora train`. Тренер берёт снимок отмеченных пар и обучает отдельный адаптер. Эвелин продолжает отвечать через CPU, пока GPU занят обучением. `/lora status` показывает состояние, `/lora cancel` прерывает текущий запуск.
3. Введи `/start incognito`, затем `/lora preview`, чтобы попробовать новый адаптер. `/stop incognito` возвращает прежний. В обычном сеансе `/lora apply` включает обученный адаптер для твоего текстового диалога и сохраняет выбор между запусками. `/lora off` возвращает базовую модель.

Время от времени Evelyn показывает два ответа на одну реплику. Можно вызвать сравнение вручную через `/lora compare`. Ответ `1` или `2` сохраняет выбранную пару, как и `/lora choose 1` или `/lora choose 2`.

Ручное обучение берёт отмеченные пары. Автоматическое добавляет короткие упражнения Evelyn, которые прошли её локальную проверку. Приоритет у выбранных сопутником ответов. Тренер проверяет кандидата на отдельных контрольных репликах, а приложение проверяет ответ загруженного адаптера перед автоматическим включением. `/lora off` возвращает базовую модель и отключает автоматическое включение до следующего `/lora apply`. Примеры сопутника и адаптеры лежат в `data/lora`. `/lora clear CONFIRM` очищает их вместе с упражнениями Evelyn.

## Личная жизнь Evelyn

Evelyn выбирает себе проект и продолжает его шаг за шагом, в том числе до первой реплики. Скука, любопытство, вдохновение, азарт и другие показатели влияют на выбор. Планировщик учитывает последние занятия и отдаёт приоритет доступному исследованию после трёх проектов подряд без сети. Энергия и усталость могут привести к отдыху с последующим возвратом к тому же проекту.

Если шаг недоступен, Evelyn сначала проверяет другой путь. Когда продолжить пока нельзя или самой Evelyn нужно время на доработку, она сохраняет черновик и дату возврата в очереди на потом. `/life` показывает очередь. Входящее сообщение и F10 прерывают текущий шаг. «Эвелин, приубавь пыл» отложит цель на 20 минут по умолчанию. `/pause` сохраняет паузу до `/resume`, в том числе между запусками.

Личные записи и черновики сохраняются в `data/autonomy/life.json`. Для рассказа Evelyn придумывает заголовок и замысел, пишет три сцены отдельными шагами и проверяет их вместе. При необходимости переписывает сцену по конкретному замечанию и повторяет проверку. Готовый рассказ попадает в `documents/evelyn-writing` с заголовком в имени файла. Первый повторный просмотр планируется через шесть часов. Если новый эпизод улучшает рассказ, Evelyn добавляет его в тот же файл. Старые записи с именами из шестнадцатеричных цифр получают заголовки по содержанию между проектами. Можно попросить дать заголовок конкретной записи дневника и указать её старое имя.

Рисунок в `documents/evelyn-sketches` публикуется после отдельной проверки изображения. Для чтения Evelyn использует текстовые файлы из `permissions.readableDirectories`, а записи дневника перечитывает в отдельных проектах. В инициативных репликах она может поделиться готовой работой, публичной находкой или проверенным прогрессом. Тихие часы ограничивают инициативные реплики и запуск обучения. В инкогнито личный цикл выключен.

Фоновые вопросы Google AI Mode идут через отдельный профиль Chrome без API-ключа, когда ПК простаивает. Для них нужен разрешённый ввод через `/desktop on` или постоянная настройка `permissions.desktopInput=true`, а также доступный AI Mode в этом профиле. Эвелин отправляет текстовый вопрос о публичной теме из своего списка. Если браузер недоступен, она может поискать статью на ту же тему. [Справка Google AI Mode](https://support.google.com/websearch/answer/16011537)

После неудачной задачи Evelyn может выбрать эту тему для самостоятельной практики. Поиск справки идёт по общему навыку. Повтор исходной операции предусмотрен для доступных текстовых файлов и явно запрошенных публичных HTTPS-страниц без параметров. Для задач с изменениями она разбирает учебный пример.

## Память и перенос

Обычный разговор проходит через два локальных прохода. Сначала модель уточняет смысл последней реплики по недавнему контексту, исправляет опечатки и отмечает важную неоднозначность. Затем Evelyn отвечает с учётом исходной реплики и уточнения. Чёткие команды и буквальные аргументы файловых и сетевых инструментов обрабатываются по исходному тексту. Если первый проход недоступен, сохраняется обычный ответ по оригиналу.

`/thoughts` показывает пять последних записей из `data/memory/thoughts.json`. В файле остаётся до 80 заметок с интерпретацией, результатом и выполненными проверками. Снимки и содержимое источников в этот файл не копируются. Журнал выключается через `turnProcessing.keepThoughtJournal` и очищается командой `/forget CONFIRM`.

Первый проход модели может запросить свежий снимок, если он нужен для ответа по контексту беседы. Например, «Ну, лучше стало?» после открытия нового рендера ведёт к снимку и ответу по изображению. В `/thoughts` такой ход отмечается как `Screen` с подготовкой `context`. Уточнение «без скриншота» отменяет захват для этой реплики.

Скука и одиночество накапливаются со временем, пока Evelyn работает. Разговор с основным пользователем снижает оба показателя. При высоком одиночестве и недавней активности за ПК Evelyn может один раз предложить поболтать. Если после приглашения компьютер использовался, а ответа долго не было, может появиться лёгкая обида. Она постепенно проходит. Windows сообщает об активности сеанса, поэтому Evelyn не приписывает её конкретному человеку.

При выключенном личном планировщике `needs.drawWhenBored` может запускать геометрический этюд по старому расписанию. По умолчанию для этого нужны восемь минут без ввода, низкая нагрузка и свободный рабочий стол или консоль. `needs.openPaint` открывает готовый PNG, если рабочее место всё ещё свободно.

После каждого ответа сохраняются диалог, краткие фактические заметки и изменение состояния. Скрытые рассуждения модели не сохраняются. При достижении порога или времени модель объединяет старые записи с долговременной сводкой. Новейшие записи остаются отдельно. При ошибке сжатия исходная память сохраняется. Запись атомарная, с резервной копией и ограниченным журналом; перед отправкой запросов размер проверяется токенизатором модели.

Обычный разговор генерируется отдельным текстовым запросом. После показа и начала озвучивания ответа отдельный служебный запрос обновляет факты, настроение и отношение; ошибка этого запроса не подменяет ответ. Заметки модели не выдаются за реплики пользователя, текущий вопрос передаётся один раз. Повторяющиеся пустые предложения и длинные дубли повторно генерируются до вывода. Служебные данные не имеют права запускать инструменты.

Evelyn говорит по-английски голосом Ono Anna из Qwen3-TTS 1.7B. Модель выбирает сдержанную подачу по текущей реплике пользователя и смыслу каждого предложения. Синтезатор держит модель загруженной на время реплики и готовит следующие фрагменты, пока играет предыдущий. При достаточном запасе памяти на CPU одновременно готовятся два фрагмента. Звук воспроизводится по порядку. Если в конце синтеза остаётся сильный сигнал, фрагмент генерируется ещё раз. Для резкого обрыва после повторной попытки используется Piper.

Для восстановления голоса запустите `Setup.cmd -Only Qwen-TTS -SkipBuild`. В текущей конфигурации `audio.qwenTtsDevice` задан как `cpu`, чтобы видеокарта обслуживала диалоговую модель. Значение `auto` отдаёт выбор устройства синтезатору. При сбое Qwen3-TTS оставшаяся часть реплики автоматически озвучивается настроенным голосом Piper. Для постоянного использования Piper задайте `audio.ttsEngine` как `piper`. Параметр `audio.speechRate` применяется к Piper.

Для переноса **скопируйте всю папку ComputerNeighbour**. В ней находятся и модели, и память. Установленный .NET для запуска не нужен. Приложение не создаёт службу, автозапуск или задачу Windows; запускать можно вручную и оставлять открытым. Все собственные кэши, NuGet, temp и необязательный SDK остаются здесь. Системные файлы Windows, видеодрайвер, браузер/приложения, которые вы открываете, могут иметь собственные данные за пределами папки; их размещением эта программа не управляет.

В версии 0.2.0 исправлена подача контекста обычной беседы и выбрана Qwen3.5-4B. После обновления закройте старую копию и снова запустите `Start.cmd`: в начале консоли отображаются версия и файл модели. `Start.cmd --init` восстанавливает подтверждённое имя и предпочтения из существующей переписки без запуска нейросети; переписка не удаляется. Сама модель остаётся небольшой: даже после исправлений возможны неловкие формулировки и лишние вопросы.

В версии 0.3.0 исправлена маршрутизация просьб чтения браузера, добавлены настоящий поиск, загрузка найденных статей и сохраняемые источники. Все собственные данные остаются в ComputerNeighbour; установка расширения браузера не требуется.

Общее содержимое с моделями занимает несколько гигабайт. Нейросеть остаётся в RAM/VRAM для быстрых ответов; между событиями запросов нет, PTT проверяется лёгким опросом. Для освобождения видеопамяти закройте программу. Дочерние процессы входят в Windows Job и завершаются вместе с ней.

## Проверка и сборка

```powershell
.\Start.cmd --diagnose
.\Build.cmd
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-Models.ps1
dotnet run --project .\tests\ComputerNeighbour.Tests -c Release -- --feature-smoke
dotnet run --project .\tests\ComputerNeighbour.Tests -c Release -- --dialogue-smoke
dotnet run --project .\tests\ComputerNeighbour.Tests -c Release -- --web-smoke
```

`Build.cmd` запускает регрессионные проверки и публикует self-contained приложение. Если .NET 10 SDK отсутствует, загрузится частный SDK в эту папку. Для первоначальной загрузки или восстановления используйте `Setup.cmd`; скачивание возобновляется, SHA-256 проверяется. Повторная установка моделей для обычного запуска не нужна. Версии зафиксированы в `models/dependencies.json`, фактическая поставка — в `models/installed-lock.json`; лицензии и первоисточники — в THIRD_PARTY.md.

Необязательный `--feature-smoke` использует настоящую локальную модель и отдельную тестовую память внутри `data/development-checks/`: проверяет запись отношения, подтверждённое создание/редактирование файла и пересказ искусственного текста браузера. Ваши вкладки, микрофон и реальный экран при этой проверке не читаются.

`--dialogue-smoke` прогоняет многошаговый диалог о характере, просьбу о меньшей инициативе, имя Влад, продолжение разговора, проверку имени после перезапуска и восстановление из прежнего неудачного контекста. Это проверка настоящей модели, а не заранее заданных ответов. Отчёт остаётся в отдельном `data/development-checks/dialogue-smoke-*/report.json`.

`--web-smoke` требует интернет и проверяет настоящий поиск, загрузку статьи Happymax, пересказ моделью, свежую техноновость и сохранённые источники. Использует изолированную память; пользовательские вкладки и микрофон этот сценарий не читает.

На этом компьютере обнаружена RTX 3070 Laptop 8 ГБ; используется Vulkan через видеодрайвер. При проблемах с GPU: `Setup.cmd -Backend cpu -SkipBuild` и `model.gpuLayers=0`. CPU будет медленнее. Если занят порт 18389, завершите предыдущую копию либо измените `model.endpoint`. `model.autoStart=false` позволяет подключить уже запущенный совместимый локальный llama-server с моделью и projector.

## Границы первой версии

- Сопоставление голосов использует локальные MFCC-признаки и регистрацию каждого человека. Это приблизительная идентификация: короткая, шумная и смешанная речь остаётся неизвестной. Надёжная нейронная диаризация и разделение одновременных голосов ещё не реализованы; неизвестным записям выдаются отдельные метки, чтобы не объединять их факты автоматически.
- Ответ генерируется целиком, затем озвучивается. Это PTT-диалог с задержкой обработки, без непрерывного прослушивания и потокового дуплекса.
- Захват экрана реализован для основного монитора. В изолированной сессии разработки Windows вернула `Access Denied`; реальный захват требует обычного интерактивного рабочего стола. Зрение модели отдельно проверено на искусственном изображении. Исключения по заголовку активного окна не скрывают чувствительные данные в других видимых окнах.
- По умолчанию используется Qwen3.5-4B Q4_K_M с соответствующим vision projector; прежняя Qwen2.5-VL-3B оставлена на диске для ручного отката. Новая модель проверена на этой RTX 3070 8 ГБ, но всё ещё может ошибаться в фактах, действиях и памяти. Локальные заметки и журналы хранятся обычным текстом/JSON.

## Расширение

Бизнес-логика находится в `Application/CompanionEngine.cs`. `IChatModel` отделяет модель, `ICompanionOutput` — вывод, `ICompanionTool` / `ToolRegistry` — инструменты. Модули `Memory`, `Personality`, `Audio`, `Platform`, `Context` независимы. Новому инструменту нужны имя, описание аргументов, признак изменения компьютера и `ExecuteAsync`; зарегистрируйте его в `ToolRegistry.BuiltIn`. Перед выполнением инструмент обязан проверить собственное разрешение. Для GUI можно подключить другой `ICompanionOutput` и перенести консольные команды в обработчики интерфейса, сохранив память и модель.
