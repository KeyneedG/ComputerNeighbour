# ComputerNeighbour

Переносимый консольный компаньон для Windows 10/11 x64 на C# / .NET 10. Локальные Qwen3.5-4B, Whisper и Piper работают без облачного аккаунта и API-ключа. Модели и движки уже загружены в эту папку; опубликованное приложение содержит .NET runtime.

## Запуск

Дважды щёлкните **Start.cmd**. Дождитесь `Ready`, затем пишите по-русски или по-английски. Персонаж отвечает по-английски текстом и женским голосом. Начальный персонаж — Evelyn; его описание можно полностью заменить.

**Удерживайте F10**, говорите, затем отпустите. Микрофон открывается только на время удержания, с пределом 30 секунд; затем выполняется распознавание. F10 работает и вне окна консоли, но сама клавиша не блокируется для других приложений. В конфиге можно назначить другую клавишу. Во время прослушивания озвучивание прерывается.

Примеры запросов:

```text
Привет! Запомни, что я люблю научную фантастику.
Read this article and tell me its main point: https://example.org/article
Read documents/notes.md and remember the main points.
Open calculator.
```

Evelyn может посмотреть на основной монитор, когда вопрос требует текущего изображения, например «Чем я сейчас занят?». Команда `/look` вызывает снимок напрямую. Программа сообщает о действии заранее и отличает успешное наблюдение в этой сессии от текущего доступа. Для чтения текущей страницы браузера используйте `/browser` или «Прочитай текущую вкладку браузера». Публичную ссылку можно передать отдельно.

Для основного пользователя зарегистрируйте голос командой `/enroll user`, затем удерживайте F10 и произнесите несколько предложений. Других людей регистрируйте отдельно, например `/enroll alice`. Метка `user` связывает ваш голос с сообщениями, набранными в консоли.

## Команды

| Команда | Действие |
|---|---|
| `/help` | Справка |
| `/look` | Скриншот основного монитора и анализ моделью |
| `/browser` | Прочитать и пересказать текущую/последнюю активную вкладку браузера |
| `/read URL, имя или путь` | Прочитать публичную статью или текстовый файл |
| `/search запрос` | Найти информацию в интернете, прочитать результаты и приложить источники |
| `/news тема` | Найти свежие новости; без темы — из мира технологий |
| `/sources` | Показать сохранённые проверенные ссылки последнего поиска/чтения |
| `/write documents/note.txt \| текст` | Подготовить создание нового текстового файла |
| `/edit documents/note.txt \| старый фрагмент \| новый фрагмент` | Подготовить замену точного уникального фрагмента |
| `/pause`, `/resume` | Приостановить/возобновить наблюдение и инициативные реплики; текст и PTT остаются доступны |
| `/mute` | Включить/выключить голос |
| `/devices` | Номера устройств записи и воспроизведения |
| `/enroll your_name` | Следующая запись регистрирует голос этого человека; говорите один, несколько секунд |
| `/status` | Настроение, отношение, объём памяти |
| `/memory` | Сжатая долговременная память |
| `/relationship` | Отдельная запись текущего отношения к основному пользователю |
| `/compact` | Запустить сжатие памяти сейчас |
| `/forget CONFIRM` | Удалить память диалога и её резервные копии; настроение и голоса сохраняются |
| `/approve 1`, `/reject 1` | Принять или отклонить конкретное действие на компьютере |
| `/exit` или Ctrl+C | Завершить работу |

## Настройки

Все настройки находятся в **config/appsettings.json**. После изменения настроек перезапустите программу. Файл персонажа **characters/neighbour.md** перечитывается перед ответами.

| Раздел | Что менять |
|---|---|
| `characterFile`, `characterName`, `userName` | Файл промпта и отображаемые имена |
| `audio.inputDeviceId`, `audio.outputDeviceId` | `-1` — системное устройство; остальные номера показывает `/devices` |
| `audio.pushToTalkVirtualKey` | Windows VK-код: F9=120, F10=121, F11=122 |
| `audio.speechRate` | Скорость речи 0.5–2.0; голос задаётся `piperModel` |
| `audio.speakerRecognitionEnabled`, `speakerMatchThreshold` | Сопоставление зарегистрированных голосов; меньший порог строже |
| `permissions` | Микрофон, скриншоты, заголовок окна, сеть, файлы, запуск приложений, ввод мышью/клавиатурой |
| `permissions.allowedApplications` | Словарь разрешённых имён и exe; аргументы и shell-команды модель выполнять не может |
| `permissions.readableDirectories` | Папки для чтения и поиска по имени. По умолчанию `documents`. Можно явно добавить абсолютный путь к локальной папке |
| `permissions.readOpenDocuments` | Разрешить чтение открытых вкладок Блокнота при включённом `readFiles` |
| `permissions.writeFiles`, `writableDirectories` | Разрешение записи и каталоги для неё; по умолчанию `documents` |
| `permissions.fullFileAccess` | `false`: самостоятельные изменения требуют подтверждения; `true`: файловые действия применяются сразу в разрешённых каталогах, включая инициативу персонажа |
| `permissions.allowAutonomousFileActions` | Разрешить персонажу самому предлагать файловые изменения; `false` оставляет только действия по запросу пользователя |
| `permissions.confirmFileChanges` | Подтверждать файловые изменения по запросу пользователя; общий `confirmActions` тоже действует, если не включён `fullFileAccess` |
| `permissions.maxWritableFileBytes` | Предельный размер редактируемого файла; по умолчанию 1 МБ |
| `permissions.readBrowser`, `browser` | Чтение браузера, список процессов, лимит текста и таймаут |
| `permissions.searchWeb`, `internet` | Поиск в интернете, провайдеры, лимиты результатов и RSS-источники техноновостей |
| `internet.lookupUnfamiliarTerms` | Искать значения сленга и незнакомых терминов по контексту вопроса |
| `permissions.confirmActions` | По умолчанию действия изменения компьютера требуют `/approve N`; запрос действует две минуты |
| `permissions.desktopInput` | По умолчанию `false`; для кликов и ввода установите `true` |
| `desktop.excludedWindowTitles` | Не наблюдать экран при активном окне с указанным фрагментом заголовка |
| `observation.includeScreenInUserTurns` | Добавлять экран к обычным пользовательским запросам; по умолчанию `false` |
| `observation.screenIntervalSeconds` | Интервал скриншотов для инициативных наблюдений; по умолчанию 180 секунд |
| `observation.keepScreenshots` | `false`: изображения живут в памяти процесса; `true`: хранить последний снимок внутри `data/tmp` |
| `proactive` | Базовый период 600–1800 секунд; до первого сообщения в сессии персонаж молчит, смена окна по умолчанию не вызывает реплику |
| `proactive.quietStartHour`, `quietEndHour` | Тихие часы по системному местному времени; 0–8 по умолчанию; равные значения отключают тихие часы |
| `weather` | Широта, долгота и интервал погоды Open-Meteo; дополнительно включите `permissions.weatherNetwork` |
| `memory` | Пороги краткой/долгой памяти, сжатие после 12 часов, размер журнала |
| `model` | Контекст, температура, потоки CPU, GPU-слои, таймауты и локальные файлы модели |

Клики используют физические координаты основного монитора. При `/approve` для ввода есть три секунды, чтобы переключиться в нужное окно. Модель получает уменьшенное изображение; точность мелких элементов ограничена. При выключенном подтверждении разрешённые действия выполняются сразу после запроса модели. Настройки разрешений применяются программой независимо от промпта.

Наблюдения и инициативные реплики работают, пока приложение запущено. В тихие часы и при длительной неактивности пользователь не беспокоится; после двух реплик без ответа персонаж ждёт обращения. Модель может выбрать молчание. Инициативные события не выполняют компьютерные действия.

Явные просьбы «называй меня Влад», «будь прямее», «поменьше инициативы», «не говори лишь бы что-то сказать» сохраняются в `data/memory/user-profile.json` из слов основного пользователя. Имя не зависит от сжатия беседы или догадок модели; `User` является внутренней меткой, а не именем. Просьба снизить инициативу втрое увеличивает интервалы планировщика. При обновлении профиль восстанавливается из сохранённых пользовательских сообщений, сама переписка остаётся на месте.

Настроение — симуляция персонажа: сохраняются доверие, теплота, близость, эмоциональный тон, энергия, стресс, любопытство. На контекст влияют диалог, успех задач, время, день недели, сезон, длительность отсутствия, активное окно, длительность сессии, заряд/питание ноутбука, экономия батареи, свободная RAM и настроенная погода. Системный контекст отключается через `permissions.systemStatus`. Без координат погода не выдумывается.

## Создание и редактирование файлов

Можно обратиться обычным текстом, например `Создай файл documents/note.txt: Remember to take a break.` или `Edit documents/note.txt | take a break | drink water`. Для произвольного задания модель может запросить `create_file` / `edit_file`. Явные команды `/write` и `/edit` работают без необходимости полагаться на выбор инструмента маленькой моделью. Разделители вокруг старого/нового фрагмента в краткой команде не являются частью содержимого; точное содержание со значимыми пробелами можно передать модели как аргументы инструмента.

Изменение сначала готовится без записи целевого файла. Консоль показывает diff, а полное предложение сохраняется в `data/file-proposals/`. По `/approve N` применяется именно просмотренный вариант. Если файл с тех пор изменился, предложение отклоняется. Новые файлы не перезаписывают существующие; при редактировании старая версия сохраняется побайтно в `data/file-backups/` вместе с метаданными восстановления. Сохраняются UTF-8/UTF-16 BOM и стиль перевода строк.

Если хотите выдать полный файловый доступ, измените существующее поле в конфиге на `"fullFileAccess": true` и перезапустите программу. В этом режиме файловые изменения по запросу и по инициативе персонажа выполняются без подтверждения. Резервные копии, проверка размера и границы `writableDirectories` сохраняются. `writeFiles=false` запрещает запись даже при полном доступе; `allowAutonomousFileActions=false` отдельно запрещает инициативные изменения.

Полный файловый доступ относится к выделенной рабочей области внутри ComputerNeighbour. Внутренние настройки, исполняемые файлы, модели, исходники приложения и его память не являются пользовательской файловой областью. Поддерживаются обычные текстовые форматы `.txt`, `.md`, `.json`, `.csv`, `.tsv`, `.html`, `.htm`, `.css`, `.xml`, `.yaml`, `.yml`, `.ini`. Бинарные файлы и исполняемые скрипты этот редактор не меняет.

## Чтение и поиск файлов

«Прочти текст в открытом блокноте PVP1.txt» запрашивает текущий текст соответствующей вкладки Блокнота, включая несохранённые правки. Вкладка должна быть выбрана в своём окне, а окно развёрнуто. Если есть только имя файла, Evelyn сначала проверяет Блокнот, затем ищет точное имя в `permissions.readableDirectories`. Команда «Найди файл PVP1.txt» сообщает, где он находится. При нескольких совпадениях Evelyn попросит точный путь. `Start.cmd --document-diagnose PVP1.txt` проверяет чтение Блокнота без запуска модели и выводит только размер текста.

## Чтение открытого браузера

Откройте нужную страницу в Chrome, Edge, Firefox, Brave, Opera или Vivaldi, ненадолго оставьте окно активным, затем вернитесь в консоль и выполните `/browser`. Приложение запоминает последнее активное окно браузера лёгким опросом. Текст страницы читается только по запросу инструмента, через Windows UI Automation; нажатия клавиш, буфер обмена, отладочный порт и отдельный профиль браузера не используются.

Читается текст документа, предоставленный средствами доступности. Поэтому могут работать уже открытые страницы с JavaScript и авторизацией. Это не гарантирует чтения всей страницы: виртуализованные списки, canvas и ещё не загруженные части могут не предоставлять текст. При нескольких неоднозначных окнах, смене страницы в процессе чтения или недоступном документе приложение сообщает ограничение и не выдаёт заголовок окна за текст статьи. Приватные/исключённые заголовки из `desktop.excludedWindowTitles` блокируются.

Если текст недоступен, но адресная строка читается, `browser.publicUrlFallback=true` разрешает загрузить публичную страницу по этому адресу (только при `permissions.readWeb=true`). В таком случае явно указывается, что cookies браузера не использовались: публичная версия может отличаться от авторизованной. Поддерживаются адресные строки, в которых скрыт префикс `https://`. Команда `Start.cmd --browser-diagnose` проверяет чтение без нейросети и печатает только заголовок, URL, способ чтения и количество символов.

Обращение по имени тоже работает: «Эвелин, можешь прочитать открытую статью в браузере и оценить её». Для гарантированного прямого вызова есть `/browser`.

## Поиск и проверенные источники

Можно прислать голую ссылку либо попросить «Найди последнюю интересную новость из мира техники и дай источник». Для обычного поиска используются публичный HTML-поиск DuckDuckGo и резервный RSS-поиск Bing; API-ключ не нужен. Для свежих общих техноновостей дополнительно используются датированные RSS-ленты издателей из `internet.technologyNewsFeeds`. Адреса, количество результатов, число читаемых статей, лимит текста и окно свежести настраиваются в конфиге. Публичные поисковые страницы иногда ограничивают доступ или показывают captcha; в этом случае приложение сообщает ошибку.

Поиск выполняется по запросу пользователя или когда текущий вопрос требует проверки значения незнакомого термина. Для такого запроса в поисковик уходит только термин с уточнением о значении. Если вы попросите перепроверить определение, Evelyn использует термин из вашего недавнего вопроса. Фоновые события поиск не запускают. После нахождения ссылок приложение загружает статьи и передаёт модели полученный текст. Если доступны только поисковые аннотации, Evelyn сообщает об этом. Старые материалы с известной датой исключаются из свежих новостей.

Ссылки добавляет приложение из результатов настоящих загрузок, а не генератор текста. Выдуманные моделью URL удаляются. Проверенные ссылки, названия и даты сохраняются в `data/memory/web-sources.json`, поэтому `/sources` и «Дай ссылку, пожалуйста» работают после перезапуска. Если для старого ответа нет проверенного источника, приложение прямо это сообщает. `/forget CONFIRM` очищает и эти ссылки. При озвучивании длинные URL не зачитываются — они остаются в консоли.

## Отдельное отношение к пользователю

`data/personality/relationship.json` хранит текущую установку к основному пользователю, последнее впечатление, ценимые качества, опасения, границы, доверие, теплоту и близость. Рядом находится читаемая проекция `relationship.md`; каноническим состоянием служит JSON. Модель получает эту запись перед ответом и обновляет её отдельно от фактической памяти и проходящего настроения. Посмотреть её можно командой `/relationship`.

Запись меняется от взаимодействий с основным пользователем (`user` или зарегистрированное имя из `userName`). Другие и нераспознанные голоса не переписывают его отношение и показатели доверия; они могут влиять на проходящее настроение. `/forget CONFIRM` очищает память диалога и оставляет отношение отдельно.

## Память и перенос

После каждого ответа сохраняются диалог, краткие фактические заметки и изменение состояния. Скрытые рассуждения модели не сохраняются. При достижении порога или времени модель объединяет старые записи с долговременной сводкой. Новейшие записи остаются отдельно. При ошибке сжатия исходная память сохраняется. Запись атомарная, с резервной копией и ограниченным журналом; перед отправкой запросов размер проверяется токенизатором модели.

Обычный разговор генерируется отдельным текстовым запросом. После показа и начала озвучивания ответа отдельный служебный запрос обновляет факты, настроение и отношение; ошибка этого запроса не подменяет ответ. Заметки модели не выдаются за реплики пользователя, текущий вопрос передаётся один раз. Повторяющиеся пустые предложения и длинные дубли повторно генерируются до вывода. Служебные данные не имеют права запускать инструменты.

```text
ComputerNeighbour/
  Start.cmd                 запуск
  Setup.cmd                 повторная загрузка/проверка зависимостей
  Build.cmd                 пересборка
  app/                      EXE и собственный .NET runtime
  config/appsettings.json   все настройки
  characters/               описания персонажей
  models/                   GGUF, Whisper, голос ONNX, контрольные суммы
  runtimes/                 llama.cpp, whisper.cpp, Piper, архивы
  data/memory/              сводка, недавний диалог, журнал, backup
  data/personality/         настроение и отношение
  data/file-proposals/      просмотренные варианты файловых изменений
  data/file-backups/        исходные байты файлов и сведения для восстановления
  data/speakers/            акустические профили зарегистрированных голосов
  data/tmp/                 временные данные (аудио удаляется после обработки)
  data/cache/, data/logs/    локальные кэши и диагностические логи
  documents/                доступные персонажу текстовые файлы
  src/, tests/, scripts/    исходники, проверки, сборка
```

Для переноса **скопируйте всю папку ComputerNeighbour**. В ней находятся и модели, и память. Установленный .NET для запуска не нужен. Приложение не создаёт службу, автозапуск или задачу Windows; запускать можно вручную и оставлять открытым. Все собственные кэши, NuGet, temp и необязательный SDK остаются здесь. Системные файлы Windows, видеодрайвер, браузер/приложения, которые вы открываете, могут иметь собственные данные за пределами папки; их размещением эта программа не управляет.

В версии 0.2.0 исправлена подача контекста обычной беседы и выбрана Qwen3.5-4B. После обновления закройте старую копию и снова запустите `Start.cmd`: в начале консоли отображаются версия и файл модели. `Start.cmd --init` восстанавливает подтверждённое имя и предпочтения из существующей переписки без запуска нейросети; переписка не удаляется. Сама модель остаётся небольшой: даже после исправлений возможны неловкие формулировки и лишние вопросы.

В версии 0.3.0 исправлена маршрутизация просьб чтения браузера, добавлены настоящий поиск, загрузка найденных статей и сохраняемые источники. Все собственные данные остаются в ComputerNeighbour; установка расширения браузера не требуется.

Общее содержимое с моделями занимает несколько гигабайт. Нейросеть остаётся в RAM/VRAM для быстрых ответов; между событиями запросов нет, PTT проверяется лёгким опросом. Для освобождения видеопамяти закройте программу. Дочерние процессы входят в Windows Job и завершаются вместе с ней.

## Проверка и сборка

```powershell
.\Start.cmd --diagnose
.\Build.cmd
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-Models.ps1
dotnet run --project .\tests\ComputerNeighbour.Tests -c Release -- --feature-smoke
dotnet run --project .\tests\ComputerNeighbour.Tests -c Release -- --dialogue-smoke
dotnet run --project .\tests\ComputerNeighbour.Tests -c Release -- --web-smoke
```

`Build.cmd` запускает регрессионные проверки и публикует self-contained приложение. Если .NET 10 SDK отсутствует, загрузится частный SDK в эту папку. Для первоначальной загрузки или восстановления используйте `Setup.cmd`; скачивание возобновляется, SHA-256 проверяется. Повторная установка моделей для обычного запуска не нужна. Версии зафиксированы в `models/dependencies.json`, фактическая поставка — в `models/installed-lock.json`; лицензии и первоисточники — в THIRD_PARTY.md.

Необязательный `--feature-smoke` использует настоящую локальную модель и отдельную тестовую память внутри `data/development-checks/`: проверяет запись отношения, подтверждённое создание/редактирование файла и пересказ искусственного текста браузера. Ваши вкладки, микрофон и реальный экран при этой проверке не читаются.

`--dialogue-smoke` прогоняет многошаговый диалог о характере, просьбу о меньшей инициативе, имя Влад, продолжение разговора, проверку имени после перезапуска и восстановление из прежнего неудачного контекста. Это проверка настоящей модели, а не заранее заданных ответов. Отчёт остаётся в отдельном `data/development-checks/dialogue-smoke-*/report.json`.

`--web-smoke` требует интернет и проверяет настоящий поиск, загрузку статьи Happymax, пересказ моделью, свежую техноновость и сохранённые источники. Использует изолированную память; пользовательские вкладки и микрофон этот сценарий не читает.

На этом компьютере обнаружена RTX 3070 Laptop 8 ГБ; используется Vulkan через видеодрайвер. При проблемах с GPU: `Setup.cmd -Backend cpu -SkipBuild` и `model.gpuLayers=0`. CPU будет медленнее. Если занят порт 18389, завершите предыдущую копию либо измените `model.endpoint`. `model.autoStart=false` позволяет подключить уже запущенный совместимый локальный llama-server с моделью и projector.

## Границы первой версии

- Сопоставление голосов использует локальные MFCC-признаки и регистрацию каждого человека. Это приблизительная идентификация: короткая, шумная и смешанная речь остаётся неизвестной. Надёжная нейронная диаризация и разделение одновременных голосов ещё не реализованы; неизвестным записям выдаются отдельные метки, чтобы не объединять их факты автоматически.
- Естественность Piper ограничена выбранным голосом: он нейронный и женский, но не поддерживает полноценное актёрское управление эмоциями. Ответ генерируется целиком, затем озвучивается; это PTT-диалог с задержкой обработки, без непрерывного прослушивания и потокового дуплекса.
- Захват экрана реализован для основного монитора. В изолированной сессии разработки Windows вернула `Access Denied`; реальный захват требует обычного интерактивного рабочего стола. Зрение модели отдельно проверено на искусственном изображении. Исключения по заголовку активного окна не скрывают чувствительные данные в других видимых окнах.
- По умолчанию используется Qwen3.5-4B Q4_K_M с соответствующим vision projector; прежняя Qwen2.5-VL-3B оставлена на диске для ручного отката. Новая модель проверена на этой RTX 3070 8 ГБ, но всё ещё может ошибаться в фактах, действиях и памяти. Локальные заметки и журналы хранятся обычным текстом/JSON.

## Расширение

Бизнес-логика находится в `Application/CompanionEngine.cs`. `IChatModel` отделяет модель, `ICompanionOutput` — вывод, `ICompanionTool` / `ToolRegistry` — инструменты. Модули `Memory`, `Personality`, `Audio`, `Platform`, `Context` независимы. Новому инструменту нужны имя, описание аргументов, признак изменения компьютера и `ExecuteAsync`; зарегистрируйте его в `ToolRegistry.BuiltIn`. Перед выполнением инструмент обязан проверить собственное разрешение. Для GUI можно подключить другой `ICompanionOutput` и перенести консольные команды в обработчики интерфейса, сохранив память и модель.
